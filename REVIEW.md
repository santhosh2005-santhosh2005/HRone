# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints).

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health()` (line 72-74) | Missing MongoDB connectivity check; always returns static `{"status": "ok"}` even if the database is down. | Stop MongoDB and send `GET /health`; it returns 200 instead of required 503. | Added `db.command("ping")` wrapped in try/except, raising `HTTPException(503)` if ping fails. |
| 2 | `create_employee()` (line 79-84) | Check-then-insert race condition (`find_one` followed by `insert_one`). Concurrent requests with the same `emp_code` can both insert. | Send concurrent duplicate `POST /employees` requests; both succeed with 201 resulting in duplicate records. | Created a unique index on `employees.emp_code` at startup and caught `DuplicateKeyError` to return 409. |
| 3 | `create_employee()` (line 81-85) | `created_at` stored as server-local naive datetime and returned as datetime/string instead of epoch milliseconds. | Inspect response body: `created_at` is an ISO datetime string instead of integer epoch milliseconds. | Truncated to seconds UTC, stored as BSON date, and converted to integer epoch milliseconds in response. |
| 4 | `EmployeeIn` model (lines 53-61) | Missing input validations: no regex pattern on `emp_code`, no email format check, no check that `shift_start != shift_end`. | Send `POST /employees` with `emp_code="INVALID"` or `shift_start="09:30"` and `shift_end="09:30"`; returns 201 instead of 422. | Added Pydantic field validators enforcing `^EMP\d{4,6}$`, valid email pattern, ISO date for `joined_on`, and `shift_start != shift_end`. |
| 5 | `list_employees()` (line 93) | Off-by-one pagination bug: `skip = page * page_size`. For page 1, it skips 20 items (skipping the first page). | Send `GET /employees?page=1`; returns empty list or page 2 items rather than records 1–20. | Fixed calculation to `skip = (page - 1) * page_size`. |
| 6 | `list_employees()` (line 94) | Filter ignored in count: `total = db.employees.count_documents({})` counts the whole collection ignoring the department filter. | Send `GET /employees?department=Sales`; `total` returns overall company count rather than department count (violating R10). | Updated to `db.employees.count_documents(q)`. |
| 7 | `list_employees()` (line 95) | Missing sorting: cursor does not specify sort order, returning unsorted documents. | Compare response against OpenAPI contract requiring sort by `emp_code` ascending. | Added `.sort("emp_code", 1)` to the query cursor. |
| 8 | `punch_in()` (lines 104-105, 118) | Check-then-insert race condition: `find_one` then `insert_one` allows two simultaneous punch-ins for same date. | Send two parallel `POST /attendance/punch-in` requests at the same instant; both get 201. | Created compound unique index on `(emp_code, date)` and caught `DuplicateKeyError` to return 409. |
| 9 | `punch_in()` (line 101) | Unhandled 500 error when employee does not exist (`TypeError: 'NoneType' object is not subscriptable` when reading `emp["shift_start"]`). | Send `POST /attendance/punch-in` with non-existent `emp_code="EMP9999"`; triggers 500 instead of 404. | Added explicit check `if not emp: raise HTTPException(404, "Employee not found")`. |
| 10 | `punch_in()` (lines 102-103) | R1 overnight shift rule ignored: `ts.date().isoformat()` assigns local calendar date, failing for overnight shifts where punch-in before `shift_end` belongs to previous day. | Overnight worker (22:00–06:00) punching in at 01:10 on 2026-07-07 gets assigned `date="2026-07-07"` instead of `"2026-07-06"`. | Implemented `compute_attendance_date` checking IST time against `shift_end` for overnight shifts (`shift_end <= shift_start`). |
| 11 | `compute_late_minutes()` (lines 33-37) | Incorrect grace period logic (`minutes > 10`), timezone mixing (`replace`), and missing sub-second truncation (R1, R2). | Punch-in at 09:40:00 (inside 10-min grace) vs 09:40:01 (10 min late). Starter code failed on edge boundaries. | Built start datetime in IST, computed `(punch_in - start).total_seconds()`, and if `elapsed > 600`, returned `floor(elapsed / 60)`. |
| 12 | `punch_in()` (line 119) | Injects `"id": str(res.inserted_id)` into response, violating OpenAPI `AttendanceRecord` schema. | Validate response against `openapi.yaml`; fails validation due to unexpected `"id"` field. | Excluded MongoDB `_id` and formatted document per `AttendanceRecord`. |
| 13 | `list_attendance()` (lines 144-147) | In-memory processing: fetches entire result set with `list(db.attendance_logs.find(q))` and sorts in Python. | Run against 100k records; causes high memory usage and query timeouts. | Performed `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)` directly in MongoDB using indexes. |
| 14 | `list_attendance()` (line 145) | Sort order only sorts by `date` desc; fails to sort by `emp_code` ascending as required by contract. | Query multiple records with the same date; order of `emp_code` is non-deterministic. | Used compound sort `[("date", -1), ("emp_code", 1)]`. |
| 15 | `list_attendance()` (lines 125-132) | Missing date range validation when `date_from > date_to`. | Send `GET /attendance?date_from=2026-07-10&date_to=2026-07-01`; returns 200 with empty list instead of 422. | Added validation raising `HTTPException(422)` when `date_from > date_to`. |
| 16 | `list_attendance()` (lines 148-150) | Injects `"id"` and returns unformatted BSON datetime objects instead of epoch milliseconds. | Inspect `punch_in` / `punch_out` in JSON; format is ISO string/datetime object instead of integer epoch milliseconds. | Implemented `serialize_record` to format all instants and history audit changes into epoch milliseconds. |

## What was examined and decided was NOT a defect
* **`compute_overtime` threshold logic**: The helper checked `max(0, ...)`; while the logic needed overnight shift date adjustment and enforcing the $\ge 30$ minute minimum threshold per R3, the overall approach of measuring elapsed minutes past `shift_end` was sound.
* **Default shift times in schema**: The defaults (`"09:30"` and `"18:30"`) in the starter schemas match the standard corporate shifts specified across `PROBLEM_STATEMENT.docx` and `DATA_MODEL.md`.
